  可验证的现象清单

  1. Workflow Tab 不再全是 0（Wave 1）

  操作：启动 daemon + web UI，打开 Workflow Tab

  之前：全部为 0，"no recent event"，或者直接报错

  现在应看到：
  - 无活跃工作流时：显示 kind: "idle" 或 kind: "unavailable" 的引导态（而非一堆 0）
  - 有工作流运行时：batches/tasks/duration/assignments 有真实数据
  - kind 不同时 UI 应有不同表现（idle 引导 vs running 统计面板）

  验证命令：
  # 直接调 API 看返回结构
  curl http://localhost:PORT/api/v1/groups/GROUP_ID/workflow/progress
  # 应返回 {"kind": "idle"|"unavailable", "reason_code": "...", "snapshot": {...}, ...}
  # 而非 {"error": "orchestrator_not_found"}

  2. Board Tab 有内容（Wave 1.5）

  操作：点击 Board tab

  之前：空白页

  现在应看到：
  - 如有 workspace tasks → 三列 kanban（planned / active / done）
  - 如无 tasks → 引导文案 "No tasks yet..."
  - Workspace / Panorama tab 也应该可点击（显示 coming soon 占位）

  3. Stop 的 Actor 不会复活（Wave 2 核心验证）

  操作：
  1. 创建多 actor 组（至少 2 个 worker）
  2. Stop 其中一个 worker
  3. 用另一个 actor 发 @all 广播消息
  4. 等待 2-3 分钟

  之前：被 stop 的 actor 在收到广播后自动恢复 enabled=true 并重新启动

  现在应看到：
  - 被 stop 的 actor 保持 stopped
  - group.yaml 里该 actor 的 admin_hold: "manual" 持久化
  - 日志出现 "Skipping auto-wake for xxx: admin_hold=manual"
  - UI 上该 actor 显示 HOLD badge

  验证命令：
  # stop 后检查 actor 状态
  cccc actor list --group GROUP_ID
  # 应看到 admin_hold=manual, enabled=false, desired_state=stopped

  # 发消息后再检查
  cccc message send --group GROUP_ID --to @all "test broadcast"
  # 再次检查 — actor 仍然 stopped，不会被唤醒

  4. group stop → start 往返正确（Wave 3）

  操作：
  1. 启动组（group start）
  2. 停止组（group stop）
  3. 再次启动组（group start）

  之前：可能存在 desired_state 和 enabled 不同步，导致 stop 后再 start 行为异常

  现在应看到：
  - group stop 后所有 actor 的 desired_state=stopped, runtime_state=stopped
  - group start 后非 held actor 恢复为 desired_state=running
  - 手动 stop 过的 actor（admin_hold=manual）在 group start 时被跳过，日志显示 skipped_held

  5. 启动工作流时 single_writer 生效（Wave 2）

  操作：通过 Ralph/API 提交一个包含 2+ 任务的 batch

  现在应看到：
  - 如果已有 running assignment → 新任务被标为 deferred (single_writer_active)
  - 如果新任务有明确的 claimed_paths 且不冲突 → 允许并行通过
  - Workflow Tab 能看到 deferred 任务

  6. service:workflow_orchestrator 身份可审计（Wave 3）

  操作：让 Foreman 启动一个工作流

  现在应看到：
  - daemon 日志中 actor_add 和 context_sync 的 by 字段为 service:workflow_orchestrator
  - 不再是 foreman 的 actor id 或 system

  7. ralph_task_event 统一入口（Wave 1）

  验证命令：
  # 直接调用 task event API
  curl -X POST http://localhost:PORT/api/v1/groups/GROUP_ID/workflow/task/completed \
    -H "Content-Type: application/json" \
    -d '{"task_id":"test","agent_id":"worker-1","workflow_id":"wf-1","duration_seconds":10}'
  # 应该走 ralph_task_event op 而非旧的 ralph_actor_status

  最直观的端到端验证路线

  如果只做一次验证，最能覆盖的流程是：

  1. 启动 daemon + web
  2. 打开 Web UI → 看 Workflow Tab (Wave 1 验证)
  3. 点击 Board Tab → 看到 kanban 或占位 (Wave 1.5 验证)
  4. 创建 3 actor 组 (foreman + 2 worker)
  5. Stop 一个 worker
  6. 发 @all 广播 → 验证 worker 不复活 (Wave 2 验证)
  7. group stop → group start → 验证 held actor 被跳过 (Wave 2+3 验证)
  8. 提交工作流 batch → 观察 single_writer/deferred (Wave 2 验证)
  9. 检查 daemon 日志中的 service:workflow_orchestrator (Wave 3 验证)
