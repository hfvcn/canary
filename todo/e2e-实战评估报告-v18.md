## 六、根因定位

### 已确认修复
- **RO-41** verify gate cwd — `plan_path` 在 CLI 端 resolve 为绝对路径 + daemon 端 fallback 到 project_root

### 部分改善
- **RO-43** retry 后 auto-dispatch — retry_task() 末尾调用 _resuggest_ready_tasks()。retry 后任务被重新 started，但最终 failed 后下游仍阻断

### 未解决
- **RO-42** challenge 假阳性 — Gemini agent 不执行代码，对安全验证逻辑产生幻觉
- **RO-39** manual auto-advance — Foreman 用 `ralph complete` 而非 `cccc task complete` 绕过引擎
- **NEW: RO-44** challenge 失败后无 foreman override 机制

### 新发现
- **RO-44** 需要 foreman override 机制：challenge 假阳性后任务进入死循环（cccc task complete 重入 verify gate），Foreman 无法强制完成
  - 改进方案：`cccc task complete --force --reason "foreman verified"` 跳过 verify gate
  - 验收标准：Foreman 可强制完成被 challenge 拦截的任务
