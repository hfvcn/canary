## 系统改进建议

### 紧急（flow 完整性）

1. **state.json HMAC 签名（FL-32）** — flow 状态文件增加签名，`ralph flow next` 每次校验后才执行 check。否则 agent 可以直接编辑 state.json 跳过任意步骤，整个 flow discipline 形同虚设。与 FL-21（Codex JSON 签名）是同一类问题的不同层面。

2. **Step 4 pre-flight check（FL-33）** — 在 step 3→4 过渡时检查 `.env` 存在且含 `CODEX_BRIDGE_SECRET`，不满足时直接 FAIL 并输出修复命令（如 `echo "CODEX_BRIDGE_SECRET=$(python3 -c 'import secrets; print(secrets.token_hex(32))')" > .env`）。

### 高优先级

3. **claimed_paths 越界检测 + 阻断（FL-29）** — 当 worker 修改 claimed_paths 之外的文件时，workflow engine 应拒绝 task complete 或至少发出 warning。app/main.py 是典型共享集成点，应在 plan 中显式声明或用 provides/consumes 约束。

4. **Step 6 归档检测重设计（FL-34）** — 不再依赖 git diff 的 `- ` 行判断删除，改为检查当前文件内容中是否仍包含已完成项的详细描述段落。或要求 flow 开始前 commit 所有工作区变更，建立干净基准。

5. **shallow_check_depth 智能检测** — 当前 heuristic 将 `python -c "asyncio.run(...)"` 误判为 compile-only。需要解析 Python 片段，检测行为操作，避免不必要的 foreman override。

### 中优先级

6. **Codex review sandbox 策略（FL-35）** — E2E flow 的 Codex review 应使用 `--sandbox workspace-write`，或在 prompt 中明确说明 sandbox 限制让 Codex 标注"环境限制"而非降分。

7. **Worker 负载均衡（FL-31）** — 自动将新 batch 任务分配给空闲 worker，而非固定 assignment map。

8. **FTS5 CJK tokenizer 最佳实践文档（RO-112）** — 在 foreman-capability-guide 中增加正确实现方式，避免每次都退回 LIKE fallback。

### 低优先级

9. **Step 2 模板增加 .env 指引（FL-36）** — 需求模板增加环境准备步骤。

10. **Step 6 check 推导透明化（FL-37）** — FAIL 输出中展示"需要删除"列表的来源和推导路径。

11. **实现任务 verification 深度（FL-30）** — plan template 中建议实现任务增加至少一个行为验证。

## 总结

v42 是一次高质量的 E2E 实测，在多个维度上显著优于 v41：

- **verification 闭环恢复**：10/11 verification_passed + 1 foreman_override（v41 全部 force_passed）
- **双 worker 真并行**：worker-1 和 worker-2 都实际执行了任务（v41 worker 未启动）
- **测试质量**：41 tests / 96% coverage / 7 安全测试
- **Foreman override 恢复路径**：T02 的 shallow_check_depth 误报被 foreman 正确 override，验证了系统韧性

综合评分 **4.3/5**，与 v32/v39 并列历史最高。
