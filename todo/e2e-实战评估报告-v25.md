## 一、结果指标（3/5）

### CRITICAL

1. **CRITICAL: [frontend/src/api.ts:3] 缺少 CORS 配置**
   - 前端固定请求 `http://localhost:8000`，后端 `backend/main.py` 未配置 `CORSMiddleware`
   - 复现路径：启动后端 `uvicorn backend.main:app`，再 `cd frontend && npm run dev`，首个 `GET /boards` 被浏览器 CORS 拦截
   - 影响：前后端完全无法联调，看板功能不可用
   - **历史对比**：CORS 是 v14/v22 也出现过的前端 CRITICAL，属于跨栈集成盲区

### WARN

2. **WARN: [backend/schemas.py:35,58] PUT 语义不够纯**
   - `ColumnReplace` 和 `CardReplace` 未包含父资源外键字段（`board_id`/`column_id`），PUT 实际是"全量覆盖可变字段"而非完整资源替换
   - 影响：严格 REST 客户端对资源表示产生误判
   - **对比 v24**：v24 的 PATCH vs PUT 混用 CRITICAL 本轮未复现，但 PUT 语义仍不完全

3. **WARN: [frontend/src/api.ts:83 + KanbanCard.tsx:19] 前端 description 类型不匹配**
   - 前端 `string | undefined`，后端接受 `string | null`
   - 影响：无法通过前端 PATCH 清空描述为 null

4. **WARN: [frontend/src/components/KanbanBoard.tsx:112] 拖拽后未同步服务端状态**
   - 拖拽调用 move API 正确，但前端只做本地重排，未用服务端响应刷新其他卡片 position
   - 影响：多次拖拽后前端 position 可能与后端偏离

5. **WARN: [backend/tests/test_api.py:64] 测试缺 column position 覆盖**
   - 卡片 CRUD+move+delete 重排+FK 约束已覆盖，但列排序回归和前后端联调未覆盖
   - 影响：column 排序 bug 可能漏检

## 七、后续改进及对应实例

### [RO-68] Verification retry 前应清理已知 artifact

**优先级**：P1
**影响维度**：过程 + 体验
**预期分数变化**：过程 4→4.5, 体验 4→4.5

**触发实例**：
> v25 T1 第二次 retry 时，首次运行产生的 `app.db` 残留在 `backend/` 目录。Verification check `smoke-crud` 使用旧 DB（无表），报 `no such table: boards`。Foreman 手工 `rm backend/app.db` 后 force-complete。
> 证据：verification_failed c894f144（10:42:02），retry_requested e59954bd（10:43:12）

**根因**：verification runner 在同一 working directory 执行 checks，不清理前次产生的副作用文件

**改进方案**：verification runner 在 retry 时增加可配置的 `cleanup_patterns`（如 `*.db`, `__pycache__`），或在临时目录中执行 checks

**验收标准**：下一轮 retry 后 stale artifact 不影响 verification 结果

---

### [RO-69] Verification 应支持跨栈集成 check

**优先级**：P1
**影响维度**：结果
**预期分数变化**：结果 3→4

**触发实例**：
> v25 T4 integration verification 通过了 backend-tests + frontend-typecheck + integration-smoke，但未检查 CORS 配置。CORS 缺失导致前后端无法联调。
> v14、v22 也有类似 CORS CRITICAL。

**根因**：verification checks 偏向单栈（后端 pytest、前端 tsc），缺少跨栈联调验证（如启动后端 → curl 带 Origin header 验证 CORS）

**改进方案**：(A) ralph validate 对全栈项目增加 `W_MISSING_CORS_CHECK` warning；(B) 能力指南中建议 Foreman 在 T4 验证中加入 CORS smoke test

**验收标准**：下一轮含前后端分离的项目，CORS 缺失被 verification 或 validate 拦截
