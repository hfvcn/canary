## 七、后续改进及对应实例

### [FIX-NEW-1] plan digest 自动同步

**优先级**：P0
**影响维度**：过程 + 体验
**预期分数变化**：过程 3→4, 体验 3→4

**触发实例**：
> v16 实战中，Foreman 执行 `ralph complete --task T2` 更新 plan.yaml state 后，`cccc task complete T2` 被 `plan_digest_divergence` 拒绝。Foreman 不得不重新 `cccc workflow submit --plan plan.yaml` 来重置 digest。5 次 divergence 事件。

**根因**：`ralph complete` 修改 plan.yaml 文件内容（更新 state.completed_task_ids），但 engine 的 plan digest 仍是旧值。两个系统修改同一文件但不互相通知。

**改进方案**：
1. `ralph complete` 执行后自动通知 engine 更新 digest；或
2. engine 在 task completion 时自动调用 `ralph complete` 并更新 digest；或
3. 取消 digest guard 对 state 字段变更的检查（仅检查 task 定义变更）

**验收标准**：Foreman 执行 `ralph complete` 后不再触发 plan_digest_divergence。

---

### [FIX-NEW-2] manual completion 触发 auto-advance

**优先级**：P1
**影响维度**：过程 + 体验
**预期分数变化**：过程 +0.5, 体验 +0.5

**触发实例**：
> v16 T2 由 Foreman 手动 `cccc task complete` 完成后，T3（depends_on=[T1,T2]）未自动推进。Foreman 需手工 re-submit plan.yaml。

**根因**：`_resuggest_ready_tasks()` 可能仅在 assigned agent 完成时触发，completer_mismatch 路径不走 resuggest。

**改进方案**：无论 completer 是否匹配，task completion 后都执行 `_resuggest_ready_tasks()`。

**验收标准**：Foreman 手动完成任务后，下游 ready 任务自动推进。

---

### [FIX-NEW-3] Worker completion protocol 强化

**优先级**：P1
**影响维度**：过程 + 体验
**预期分数变化**：过程 +1, 体验 +0.5

**触发实例**：
> v16 backend-worker 完成 T1 的实际代码后（over-delivered T2 scope），但 never called `cccc task complete T2`。frontend-worker 在 T4/T5/T6 上均不调用 task complete。

**根因**：Worker prompt 对 completion protocol 指导不足；Worker 不知道必须调用 `cccc task complete` 来闭环。

**改进方案**：
1. 在 auto-dispatch 的 task prompt 中显式强调 "完成后必须调用 `cccc task complete TASK_ID --changed-file ...`"
2. 添加 completion reminder：Worker 长时间未调用 task complete 时发送提醒
3. 考虑 Worker prompt template 中固定包含 completion 指令

---

### [FIX-NEW-4] 统一 ralph/engine 状态机

**优先级**：P2
**影响维度**：体验
**预期分数变化**：体验 +0.5

**触发实例**：
> v16 Foreman 反馈 "ralph complete 和 cccc task complete 是两个独立状态机"，需要分别操作。

**改进方案**：`cccc task complete` 成功后自动调用 `ralph complete` 同步 plan state，或反过来。

## 八、综合评分：3.0/5

**v16 总结**：规划层（ralph validate/suggest）和验证层（verify gate with real checks）保持强劲，DAG gating 和 auto-dispatch 引擎能力已就位。但 PTY Worker 执行可靠性是最大瓶颈（1/7 自主完成），加上 plan digest 同步新问题，导致整体从 v15 的 4.0 退步到 3.0。

**核心改进方向**：
1. **P0**: 修复 plan_digest_divergence 死锁（NEW-1）
2. **P0**: 提升 PTY Worker 可靠性或建立可靠的 Foreman-as-executor 兜底通道（NEW-3）
3. **P1**: manual completion 触发 auto-advance（NEW-2）
4. **P1**: Foreman 对 critical flow 任务启用 verification_mode=challenge（RO-37 应用层）
