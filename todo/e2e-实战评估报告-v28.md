## 七、后续改进及对应实例

### [RO-74] worker-be (codex) 不主动调用 cccc task complete（P2）

**优先级**：P2
**影响维度**：体验
**预期分数变化**：体验 4.5→5

**触发实例**：
> v28 实战中，worker-be 完成 T1/T2 后发送进度消息给 Foreman，但不主动调用 `cccc task complete`。Foreman 发送提醒消息后 worker 才执行（但 ledger 显示 completion 实际在提醒前已触发）。
> Foreman 反馈："Both workers reported progress via cccc send to @foreman but did NOT call cccc task complete on their own."

**根因**：[Foreman Assignment] 模板中 `cccc task complete` 指令不够突出
**改进方案**：在 auto-dispatch prompt 模板的首尾两处重复 `cccc task complete` 命令，或在 worker prompt 注入 post-execution reminder
**验收标准**：worker 在无 Foreman 提醒的情况下自主调用 `cccc task complete`

### [RO-75] workflow 全部完成后未自动转终态（P2）

**优先级**：P2
**影响维度**：体验
**预期分数变化**：体验 +0.5

**触发实例**：
> v28 实战中，3/3 tasks completed + verification_passed 后，`cccc workflow status` 仍显示 `kind: "running"`。
> Foreman 反馈："Workflow status shows 'running' even when all tasks completed."

**根因**：WorkflowOrchestrator 无终态转换逻辑
**改进方案**：当 `tasks.completed == tasks.total && tasks.failed == 0` 时自动将 workflow 标记为 `completed`
**验收标准**：全部 task 完成后 `cccc workflow status` 显示 `kind: "completed"`
