## 新发现改进项

### UX-16 Actor PTY 进程异常退出零日志 + 不自动重启（P1）

- **复现次数**：本次 E2E 中 4 次（lead x1, worker-1 x1, claude-general-worker x1, claude-general-worker-1 x1）
- **影响**：每次需手动 `cccc actor start` 重启，累计中断约 10 分钟
- **根因**：daemon `_mark_actor_stopped_on_exit` 将异常退出当正常停止，`try/except: pass` 吞掉所有日志
- **代码位置**：`server.py:832`, `actor_lifecycle_ops.py:188`, `pty.py:592`

### UX-17 Actor 进程退出时 scrollback 丢失（P2）

- `_close_all()` 在 `_on_exit` 前执行，无法事后查看 CLI 输出的错误信息

### FL-14 v40 复现：step-4 两次 Codex review 未引导并行（P2）

- Flow instruction 未提示 `run_in_background`，导致串行阻塞

## 改进建议

1. **UX-16 优先修复**：actor 自动重启 + 退出日志，消除最大的体验痛点
2. **Challenge mode 扩展验证面**：应包含 token type 混用（refresh 当 access）攻击向量
3. **审计集成验证**：需要在 verify gate 中检查 audit 是否真正被业务代码调用
4. **Failure recovery 设计**：下轮 E2E 需设计真正不可能通过的 acceptance_criteria
5. **FL-14 并行提示**：flow step-4 instruction 应明确提示两次 review 并行执行
