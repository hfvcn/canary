## 交叉验证（观察者 vs Codex 双路）

- **RV-29 闭合**：观察者 runtime 探测（落库 member + 403）与 Codex results-review（schema/runtime/DB/promote 四重证据链）**独立一致确认闭合**。这是 v49→v50 最重要的闭环。
- **弱加密（新）**：观察者未深查 secret 存储；Codex 抓出可逆 Base64 = 非加密，测试只断言「非裸明文」→ 错误安全感。判定 unsafe 的真因不在 RV-29 而在此。
- **独立验证被压制（新）**：观察者发现 plan `suppress_instances: W_CRITICAL_FLOW_WORKER_ONLY_VERIFICATION`；Codex process-review 独立指出同一点并补充 worker-a 独占 T1/T2/T3/T5、T3 challenge 抓到 ralph 全绿漏掉的 cleartext。两路一致。
- **sign-off 弱门禁（新）**：Codex 指出 `test -s + grep APPROVED` 门禁 + SECURITY_REVIEW「30 passed」vs 最终「50 passed」未绑定。观察者复核 plan check 命令证实。

## 系统改进建议（拟登记 tracker，见 step 6）

1. **FL-55（P1）独立验证告警可被 suppress_instances 静默**：`W_CRITICAL_FLOW_WORKER_ONLY_VERIFICATION` / `W_CRITICAL_FLOW_NO_INDEPENDENT_REVIEW` 不在 v50 `_NON_SUPPRESSIBLE_WHEN_SECURITY` 集，安全 critical_flow 下仍可被 plan 静默。本轮 foreman 真的这么做了。→ 纳入不可压制集，覆盖 suppress_instances 面（与 FL-52/RV-31 配套）。
2. **FL-56（P1）security sign-off gate 过弱且未绑定基线**：`grep APPROVED` 即过，sign-off 不校验 reviewer 身份/覆盖/commit/suite 基线（30 vs 50 passed）。→ sign-off 结构化（reviewer/commit/suite 摘要/时间戳）+ 门禁校验与当前状态一致。FL-49 artifact 已达成但 gate 实质可绕过。
3. **FL-57（P2）randomized check 名不副实**：缺 pytest-randomly 即退回定义序却记为 randomized passed + test_stats_reliable=true。→ check 先校验插件存在或显式注入 seed/harness，否则不得标 randomized。
4. **FL-58（P2）override/假设态与纯通过混算**：报告 100%/reliable=true 系统性高估。→ 结果分类 passed/overridden/assumption-based/independently-reviewed，任一非零禁止输出二元 reliable=true。
5. **RV-33（P2，可能已知局限）弱加密语义不可结构检测**：「加密/脱敏」需求被实现为可逆 Base64，validate/test 无法捕获。→ 安全敏感存储需求应映射为显式独立 reviewer 验收项或属性测试。
6. **UX-22（P3）SUSPICIOUS 浅检查误报噪音**：compileall/grep/test -s 天然快检查被标 SUSPICIOUS，噪音淹没真实弱验证。→ 按 check 类型基线，仅对实质测试打标。
7. **观察（角色边界）**：security-reviewer（非执行者）被派执行任务 T4，流程未阻止（completer_mismatch 仅事后捕获 worker-b 实际完成）。→ plan 写入执行者/审查者互斥并在 dispatch/complete 强校验。

## 核心教训（延续 v48/v49）

v49：「validate 0 error + verify 门全过 + security-reviewer 签核」≠「实现安全」——RV-29 提权穿透。
**v50：RV-29 这条轴已闭合**（guide 引导 + validate 告警 + 三层防御 + 独立审查共同奏效）。但同一「结构绿 ≠ 实质安全」教训在两条新轴延续：
- **弱加密轴**：结构闸门无法判断 Base64≠加密；
- **流程可信度轴**：独立验证告警可被 plan 主动 suppress、sign-off 是弱门禁、randomized/reliable 是空头支票——「流程绿灯」被系统性等同于「验证充分」。
下一步重心：把「独立验证」与「sign-off」从可绕过的软约束升级为绑定状态的硬门禁（FL-55/56）。
