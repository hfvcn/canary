## 七、后续改进及对应实例

### [RO-45] _read_claimed_paths 目录展开

**优先级**：P1
**影响维度**：过程（challenge verification accuracy）
**预期分数变化**：过程 5→5（保持），体验 3→3.5（减少假阳性重试）

**触发实例**：
> v20 T3 claimed_paths 包含 `backend/routes/`，`_read_claimed_paths()` 中 `full_path.is_file()` 对目录返回 False，source_context 中该目录标记为 `<file not found>`。challenge agent 因此误判 "source code missing"。

**改进方案**：当 `claimed_path` 是目录时，递归枚举其中的文件并逐个读取。

**验收标准**：下一轮目录型 claimed_paths 不再产生 `<file not found>`。

---

### [RO-46] challenge agent git diff 新项目兼容

**优先级**：P1
**影响维度**：过程
**预期分数变化**：体验 3→3.5

**触发实例**：
> v20 T3 首次 challenge 因 "git diff is empty" 判定失败。原因：项目无 git 历史，diff 为空是正常状态。

**改进方案**：
1. 如果 git diff 为空且 changed_files 非空，在 prompt 中注明 "no prior commits exist"
2. 或直接对比 changed_files 的磁盘存在性而非 diff
