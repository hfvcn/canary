## 七、后续改进及对应实例

### [RO-51] W_WORKER_EXCEEDED_SCOPE 目录路径误报

**优先级**：P1
**影响维度**：过程
**预期分数变化**：过程 4→4.5

**触发实例**：
> v21 T1 claimed_paths=`["backend/", "requirements.txt"]`，worker 修改 `backend/main.py` 等 5 个文件，全在 `backend/` 下，但 W_WORKER_EXCEEDED_SCOPE 判定为 "outside claimed_paths"。

**根因**：scope 检查可能用精确匹配而非目录前缀匹配

**验收标准**：`backend/main.py` 不再被判为超出 `backend/` 的 scope

### [RO-52] Gemini challenge API fallback

**优先级**：P1
**影响维度**：过程 + 体验
**预期分数变化**：过程 4→5, 体验 3.5→4

**触发实例**：
> v21 T1 连续 3 次 challenge 失败（"Gemini response was not valid JSON"），worker checks 全部通过。

**改进方案**：Gemini 返回无效 JSON 时 retry 1 次或 fallback 到 worker-only verification

### [RO-53] verification check 管道 exit code 问题

**优先级**：P2
**影响维度**：过程
**预期分数变化**：过程 +0.5

**触发实例**：
> v21 T2 的 test check 命令 `pytest tests/test_api.py -v --tb=short 2>&1 | tail -40` 中 pytest 报 ERROR 但 tail exit code=0

**改进方案**：使用 `set -o pipefail` 或改用 subshell 捕获原始 exit code

### [RO-54] 下游 auto-dispatch 需手工 re-submit

**优先级**：P1  
**影响维度**：体验
**预期分数变化**：体验 3.5→4.5

**触发实例**：
> v21 Foreman 报告 T2/T3/T5/T6 四个下游任务虽有 assignment-map 但仍需手工 `cccc workflow submit`

**改进方案**：当 DAG 门控解锁下游任务时，引擎应自动 dispatch（不需 Foreman 再次 submit）
