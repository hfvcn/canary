## 二、本轮新发现

### 🔴 RV-29（致命，新增）— 认证入口自注册提权，击穿 RBAC
- `POST /auth/register` 接受客户端提交的 `role`，服务端原样落库（`app/schemas.py:15` + `app/routers/auth.py:21-30`）；任意匿名用户可自注册为 admin/editor，再登录拿高权 token，使下游所有 owner/share/角色校验失效。
- **系统级问题**：validate、8 个 verify 门、codex 安全审查、全量回归**全部放行**。测试甚至把该行为固化为「正确」(`tests/test_auth.py`、`tests/test_integration.py` 注册时带 role 并断言成功)。
- 暴露 CCCC 闸门盲区（RV-22 的「身份获取面」延伸）：**没有任何机制要求「认证/注册/角色变更入口的字段权限边界」纳入安全关键流必检项**；critical_flows 声明了 auth/RBAC/share，但 verify 仅检查「文档资源面」越权，未覆盖「身份获取面」提权。

### FL-52（新增）— `W_AGENT_REVIEW_SKIPPED` 可被 suppress_codes 静默压制
- 既然安全敏感流强制要求 reviewer 参与（FL-45），「评审被跳过」告警却可被 plan.yaml 一行 `suppress_codes`（`plan.yaml:63-64`）关掉，使「reviewer 缺席/未留痕」无任何阻断信号。建议：安全关键流下该 code 不可被 suppress，或 reviewer 参与需以可审计 artifact（review 产物/签核记录/commit）证明（与 FL-49 配套）。

### FL-53（新增）— validate 判定随文件系统状态漂移
- 计划期 `ralph validate` 0 error；源码就位后才冒出 `E_FORBIDDEN_FLOW_UNCOVERED`（forbidden_flow 未被 covers.flows 覆盖）。同一份 plan 判定结果不稳定，给「计划期已达标」假象。建议：此类覆盖校验在计划期即强制。

### FL-54（新增）— 全量回归门 × 故意失败的外部用例 = 死结，无预警
- T8 的 `full-regression=pytest -q` 会把 T7 已 override 的 Redis 用例永久拉红，形成死结；框架未预警。最终靠把用例改 `importorskip+ping-skip` 解。建议：validate 在「任务以全量套件验证 + 计划内存在将 override/故意失败用例」时预警。

### UX-20 / UX-21（体验，新增）+ 沿袭项
- **UX-20 stall 心跳误报（最影响判断）**：`idle_for>300s` 基于 task 级心跳，不随 worker 实际产出(token/写盘)刷新；T3/T7/T8 在 actor 级 idle=0 时仍被反复判 stalled（最长≈728s），诱导重启 exec-b/exec-c。建议心跳随文件写入/工具调用/token 刷新，或纳入 actor 级 idle。
- **UX-21 CLI/文档不符**：指南 Evaluation Loop 写 `cccc model rate <model> <score>`，CLI 仅有 `cccc model review`，`rate` 不存在（v48 已记录的 flow 指令缺陷，仍未修）。
- **reply_required/nudge 噪声**（次要）：`cccc reply --by foreman` 不清 reply_required（需 `--by <真实 actor id>`）；同条 stall/REPLY 提醒每 ~30s 重复推送。
- **worker 冷启动零产出**（次要）：exec-b/exec-c 首发约 5 分钟零产出，是本轮唯一一次需重启干预的根因（UX-14 已修首任务 T1 阈值，非首任务仍未覆盖）。

## 三、正面信号（机制确实帮上忙）

- **verify 门抓到 2 个真实缺陷**（本轮最大价值）：T4 worker 自带测试误判「viewer+write-share 应可写→200」与规范冲突，门拦下 `assert 403==200`→retry→精准修复；T8 集成测试误用 `client.patch` 调 `PUT` 端点→405，门拦下并修正。
- **`--auto-dispatch` 按 DAG 自动流转**，依赖顺序零错乱，无需逐批手工 submit。
- **contracts(provides/consumes)+depends_on** 让 ralph 正确算并行批次与拓扑序。
- **override 对外部依赖缺失顺滑**：T7 限流无 Redis 失败，`override --reason --evidence` 一步收口，区分 infra_dependency 与 task_quality。
- **FL-45 落地**：安全敏感需求下确实创建了非执行者 codex reviewer（非 executor-only team）。
