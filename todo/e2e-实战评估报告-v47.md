## Codex 审查发现

### Results Review（总评 3/5）

| 维度 | 评分 | Codex 发现 |
|------|------|-----------|
| JWT 安全 | 2-4/5 | sub 绑定可变 username（改名后 token 失效）；is_active 未检查 |
| 密码哈希 | 3/5 | bcrypt 正确但无 72 字节截断处理、无密码强度策略 |
| RBAC | 2/5 | /search 公开返回 email/role，缺统一权限层 |
| SQL 注入 | 4/5 | ORM 参数化正确，LIKE 通配符未转义但不是注入 |
| CJK 搜索 | 3/5 | LIKE fallback 可用，无归一化/通配符转义 |

### Process Review（总评 3/5）

| 维度 | 评分 | 发现 |
|------|------|------|
| Plan 质量 | 4/5 | critical_flows/forbidden_flows/provides/consumes 完整 |
| Verification | 3/5 | 类型齐全但全量测试不稳定（test_routers 隔离问题） |
| 代码组织 | 3/5 | 清晰但 router 层过重（无 service 层） |
| 错误处理 | 2/5 | 基础 HTTPException，缺 IntegrityError 映射 |

### 实现缺陷（Codex 发现）

1. **`is_active` 字段未被检查**（Medium）— 模型有 is_active 但 login/auth 不检查
2. **JWT sub 绑定可变 username**（Medium）— 改名后旧 token 失效
3. **`/search` 公开暴露 email/role**（High）— 未要求认证
4. **`update_me` 缺唯一性校验**（Medium）— 冲突时 500
5. **tokenUrl 不一致**（Low）— `/api/login` vs 实际 `/api/users/login`

### Workflow 缺陷（观察发现）

1. **T1/T2 challenge verification 过于严格** — 代码正确但 challenge 失败，需要 foreman override
2. **test_routers.py 隔离问题** — 模块级共享状态，4 个测试失败
3. **无 git commit** — workspace 无提交历史，影响可追溯性
4. **WORKFLOW_EVALUATION.md 过于简单** — 自动生成 stub，缺详细分析
