## 待解决

### FIX-E2E-3 Worker 不发 heartbeat 导致 running 状态不可观测（P2）
> **来源**：2026-04-19 E2E v12 实战
> **更新（2026-04-22）**：auto task_started 已实现；PROGRESS REPORTING 指引已加入 worker prompt 和 orchestrator prompt section。v14 未观察到 heartbeat 事件，待下轮验证。
- **严重度**：Medium — 监控显示长期 `assigned`，无法区分 "worker 在工作" vs "worker 卡住"
- **现状**：代码已修复（auto task_started + prompt heartbeat 指引），但 v14 E2E 未观察到 worker 实际发送 heartbeat
- **验收标准**：E2E 中 task_started 在 batch_approved 后秒级出现（✅ 已达成），worker 定期发送 heartbeat（待验证）

### FIX-E2E-5 ralph validate 事件无可审计记录（P2）
> **来源**：2026-04-19 E2E v13 实战
> **更新（2026-04-22）**：`_write_validation_event()` 已实现，支持 `workflow.plan_validated` / `workflow.plan_validation_failed` 事件。但 v14 Foreman 执行 `ralph validate` 时未传 `--group` 参数，ledger 中无事件。
- **严重度**：Medium — 代码已实现但依赖 Foreman 传递正确参数
- **改进方案**：
  1. ralph validate 自动检测当前 group（从 project_root 反查 attached group），无需手工传 --group
  2. 或在 Foreman 能力指南中明确要求传 --group 参数
- **验收标准**：ledger 中出现 `workflow.plan_validated` 事件，时戳早于同一 plan 的 batch_registered 事件

### FIX-E2E-7 Workflow retry 创建竞争 workflow_id（P1）
> **来源**：2026-04-22 E2E v14 实战
- **严重度**：High — Worker 无法完成任务，Foreman 被迫手工 force-complete
- **现象**：T1 首次 verification_failed 后，Foreman 执行 `cccc workflow submit` 创建了新 workflow_id `notes-app-retry`，与原 `notes-app-v1` 竞争同一 task_id T1。Worker 调用 `cccc task complete T1` 遇 `workflow_id_mismatch` 循环 3 次失败
- **根因**：`cccc workflow submit` 允许对已注册 task_id 创建新 workflow，engine 在 task complete 时无法确定哪个 workflow 拥有该 task
- **改进方案**：
  1. 同一 group 中禁止重复 task_id 跨 workflow 注册，submit 时检测冲突
  2. 或 `cccc workflow retry TASK_ID` 复用原 workflow_id，重置 task 状态
- **验收标准**：retry 后 Worker 可直接 `cccc task complete` 无 mismatch 错误

### FIX-E2E-8 Terminal failed 状态阻止 re-completion（P2）
> **来源**：2026-04-22 E2E v14 实战
- **严重度**：Medium — Worker 修复代码后无法触发重新验证
- **现象**：T4 verification_failed（环境问题：proxy + 端口冲突），Worker 修复 integration_test.sh 后 `cccc task complete` 返回 `terminal_state:failed`。脚本手动运行通过但引擎状态无法更新
- **根因**：failed 是 terminal 状态，WorkflowEngine 不允许 failed→completed 转换。缺少"可重试失败"概念
- **改进方案**：
  1. 新增 `failed_retryable` 状态，允许重新 complete
  2. 或 `workflow retry TASK_ID` 将 failed task 重置为 ready，走正常 assign→complete 流程
- **验收标准**：failed task 可通过 retry 重新进入 ready→assigned→running→completed 流程
