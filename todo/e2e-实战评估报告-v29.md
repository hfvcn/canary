## 七、后续改进及对应实例

### [RO-77] workflow 自动终态缺少 ledger 事件

**优先级**：P1
**影响维度**：过程
**预期分数变化**：过程 4→5

**触发实例**：
> v29 实战中，8/8 任务全部 completed+verification_passed 后，`cccc workflow status` 返回 `kind=completed`，但 ledger 中无 `workflow.completed` 事件。Codex 过程审查判定"RO-75 无日志证据"。

**根因**：workflow_state_engine 转终态时更新了内部状态但未发射 ledger 事件。

**改进方案**：在 workflow 状态转为 completed/failed 时发射 `workflow.completed` / `workflow.failed` 事件到 ledger。

**验收标准**：下一轮实战中，所有任务完成后 ledger 包含 `workflow.completed` 事件。

### [RO-78] Foreman retry 创建新 workflow_id

**优先级**：P2
**影响维度**：体验
**预期分数变化**：体验 +0.5

**触发实例**：
> v29 T8 codex stall 后，Foreman 尝试用 `kanban-v1-fix` 新 workflow_id 重新注册，触发 `workflow_id mismatch` 错误（行 142）。需要用户手工指导"在现有 workflow 中 retry"。

**根因**：Foreman 对 `cccc workflow submit --plan` 的 retry 语义理解不准确，以为需要新 workflow。

**改进方案**：在 foreman-capability-guide.md 中明确说明 retry 只需重新 submit 相同 plan（已完成任务自动跳过），或使用 `cccc workflow retry`。

**验收标准**：下一轮实战中，Foreman retry 不创建新 workflow_id。

---

### [RO-79] mock_test verify_command 语法/逻辑错误无法 validate 时检测

**优先级**：P2
**影响维度**：体验
**预期分数变化**：体验 +0.25

**触发实例**：
> v29 T1 的 mock_test_2 verify_command 包含 `python -c 'if False ...'` 逻辑错误。ralph validate 通过但 verification 时失败。

**根因**：ralph validate 不解析 verify_command 中的 Python 代码。

**改进方案**：对 `python -c` 类型的 verify_command 做 `compile()` 语法检查（不执行）。

**验收标准**：下一轮实战中，Python 语法错误的 verify_command 在 validate 阶段报 warning。
