## 七、后续改进及对应实例

### FIX-E2E-7 Workflow retry 创建竞争 workflow_id（P1）

**触发实例**：v14 T1 首次 verification_failed 后，Foreman retry 创建了 `notes-app-retry` workflow_id，与原 `notes-app-v1` 竞争同一 task_id。Worker 调用 `cccc task complete T1` 时遇 `workflow_id_mismatch`，循环 3 次失败。

**根因**：`cccc workflow submit` 允许对已注册 task_id 创建新 workflow，engine 无法确定哪个 workflow 拥有该 task。

**改进方案**：(a) 同一 group 中禁止重复 task_id 跨 workflow，或 (b) retry 复用原 workflow_id。

**验收标准**：retry 后 Worker 可直接 `cccc task complete` 无 mismatch。

### FIX-E2E-8 Terminal failed 状态阻止 re-completion（P2）

**触发实例**：v14 T4 verification_failed（环境问题），Worker 修复脚本后 `cccc task complete` 返回 `terminal_state:failed`。

**根因**：failed 是 terminal 状态，不允许再次 complete。缺少"可重试失败"状态。

**改进方案**：新增 `failed_retryable` 状态，或允许 failed task 通过 `workflow retry` 重置为 ready。

**验收标准**：failed task 可通过 retry 重新进入 ready→assigned→running 流程。

### RO-24 Verification checks 跨 task scope 未检测（P2）

**触发实例**：v14 T1 的 verification check `test_backend` 执行 `pytest backend/tests/`，但 `backend/tests/` 属于 T2 的 claimed_paths。T1 首次 verification_failed 因为 T2 的测试目录还不存在。

**根因**：ralph validate 检查 claimed_paths 声明但不检查 verification.checks 中的命令是否引用了其他 task 的 scope。

**改进方案**：validate 新增规则：解析 checks[].command 中的路径引用，如果引用了不在当前 task claimed_paths 中的路径，报 `W_VERIFICATION_CROSS_SCOPE` warning。

**验收标准**：T1 的 check 引用 `backend/tests/`（T2 scope）时 validate 报 warning。
