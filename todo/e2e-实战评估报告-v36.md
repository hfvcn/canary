## 一、结果指标（3/5）

**审查者**：Codex（read-only sandbox 对抗式代码审查）
**评分**：3/5（"Solid functional baseline, but SSRF is check-time-only and several URL/auth hardening gaps keep it from production-ready"）

### CRITICAL (2)

| # | 文件:行号 | 问题 | 影响 |
|---|----------|------|------|
| R-1 | app/main.py:94 | **redirect-time SSRF 缺失**：SSRF 校验仅发生在 POST /shorten 入库时；GET /{code} 重定向未重解析存储的 URL，已通过 DNS rebinding 攻击窗口 | 入库时为公网、跳转时已 rebinding 到内网 |
| R-2 | app/security.py:73 | **编码 IP 旁路**：依赖 ipaddress + getaddrinfo，未显式拒绝非规范 IPv4 编码（如 `http://0177.0.0.1/` 八进制形式被接受） | 通过 octal/hex 主机绕过 SSRF 黑名单 |

### WARN (4)

| # | 文件:行号 | 问题 | 影响 |
|---|----------|------|------|
| R-3 | app/main.py:96 | **redirect chain 旁路**：存储的公网 URL 可指向 open redirect → 私网目标；shortener 只验证首跳 | SSRF 间接绕过 |
| R-4 | app/main.py:80 | **DELETE token 非常量时间比较**：用 `!=` 比较 ADMIN_TOKEN 而非 secrets.compare_digest | timing attack |
| R-5 | app/security.py:56 | **URL 输入校验不足**：无显式长度限制、未拒控制字符/NUL、unicode host/path 未规范化 | 边界依赖下游 |
| R-6 | app/security.py:91 | **userinfo 误导**：`http://attacker@public.com` 类 URL userinfo 被保留 → 重定向时可误导用户 | 钓鱼向量 |

### INFO (5)
- R-7 IPv6 SSRF：实现拦截 ::1 + is_private，但测试只覆盖 ::1，未测 fc00::/7 / fd00::/8
- R-8 custom_code：3-20 ASCII alphanumeric，正确拒绝 unicode/NUL/path
- R-9 SQL injection：parameterized queries，无字符串拼接
- R-10 错误处理：debug=False，HTTPException 无 traceback 泄露
- R-11 测试覆盖：96 tests 通过，缺：redirect-time DNS rebinding / fc00 IPv6 / 编码 IP 矩阵 / userinfo / NUL+length+unicode / timing-safe / redirect chain bypass

## 六、根因定位

### 体验高 ≠ 结果高的本质
- verification.checks[] 验"声明过的"行为（goal_behavior + critical_flows），不验"未声明的"安全边界
- foreman plan 时声明的 critical_flows 已尽力（SSRF、admin auth、code uniqueness）
- 但 **redirect-time DNS rebinding** 是部署时序问题，**octal IP encoding** 是输入规范化问题——这些不在 goal_behavior 自然语言里
- agent review pass（verification_mode: ralph）依赖 reviewer 主动审，未覆盖编码矩阵 / 时序

### v36 新发现
- **e2e 任务的 verification.checks 缺 compile step**（仅全量 pytest + README grep）——P-1
- **provides/consumes 仍是元数据**，dependency 失败需通过 import 间接暴露——P-2
- **plan.yaml state 字段不持久化 workflow 完成**——P-5（dual source of truth）

## 七、后续改进

### RO-92: verify gate 缺 TOCTOU 审查能力（P1，源自 R-1）
- **触发实例**：v36 plan 声明 ssrf_protection critical_flow，pytest 仅覆盖 POST /shorten 入库校验，未追问 GET /{code} 跳转是否重解析→ DNS rebinding 窗口逃过 gate
- **改进方案**：critical_flow 增加 `temporal_pattern: store_then_use | check_then_act | reserve_then_consume`；含该字段时 verify gate 注入两阶段测试（store 合法、use 时 mock 状态变化），未覆盖时报 W_VERIFICATION_TOCTOU_GAP
- **范围说明**：FastAPI 项目本身的 hook（`SSRF_REVALIDATE_ON_REDIRECT=true`）是示例修复，不计入 CCCC 改进项

### RO-93: verify gate 增加 hostname 编码规范化 smoke test（P1，源自 R-2）
- **触发实例**：v36 八进制 IP `0177.0.0.1` 通过校验
- **改进方案**：verify gate 对接受 URL 的服务自动注入 `[0177.0.0.1, 2130706433, [::ffff:127.0.0.1]]` 矩阵

### RO-94: verify gate 应对 auth 字段做 timing-safe 检查（P2，源自 R-4）
- **触发实例**：v36 ADMIN_TOKEN 用 `!=` 比较
- **改进方案**：plan critical_flow 含 "*_auth" 时，verify gate grep secrets.compare_digest 或 hmac.compare_digest

### FL-8: e2e 任务自动注入 compile check（P2，源自 P-1）
- **触发实例**：v36 e2e 任务 checks 只有 pytest + grep
- **改进方案**：ralph validate 对 verification_mode=ralph 的非 unit task 强制要求 compile step

### FL-9: provides/consumes 应可声明 signature 并机器校验（P2，源自 P-2）
- **触发实例**：v36 4/4 任务 provides/consumes 是文字标签
- **改进方案**：扩展 provides schema 允许 `signatures: {fn_name: "(args) -> ret"}`，consumer task 启动前用 ast 校验

### FL-10: plan.yaml 自动持久化 workflow 完成态（P3，源自 P-5）
- **触发实例**：v36 plan.yaml task state 与 ledger 不一致
- **改进方案**：workflow 状态转移时 hook 回写 plan.yaml（或读时合并 ledger）

### 仍待修复（v36 遗留 v35b 项目）
- RO-89/90/91 (v35b)：verify gate FTS5 smoke / debug=True / claimed_paths 一致性
- RL-26, FL-4/5/6 (v36 之前)：placeholder 误报、guide --output 覆盖、dev 分支 warning 阻塞、step-4 不区分新旧变更
