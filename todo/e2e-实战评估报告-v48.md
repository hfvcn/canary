## Codex 审查关键发现

### 实现缺陷（results review，`tests_actually_pass: true` 但结论不稳）
- **P1 测试隔离**：`tests/test_auth.py:34-59` client fixture 非 reload-safe，与 `test_config.py` 的 `importlib.reload(app.database)` 产生真实顺序依赖，反序执行失败。
- **P2 RBAC 策略例外**：`app/projects.py:63-75` `POST /projects` 无角色门禁；`tests/test_rbac_matrix.py:55-64` 把此行为固化为成功路径。
- **P2 授权矩阵不完整**：同项目 `GET /projects/{id}/tasks/{task_id}` 缺三角色矩阵用例；"project admin 但非 owner"写权限无集成测试。
- 优点：task/project 写授权双层校验（角色+归属）到位、cross-project IDOR 经 project-scoped 404 阻断、JWT 算法固定 + 过期/篡改/伪造统一 401。

### 过程缺陷（process review，score 2/5）
- **P1 reviewer 无留痕**：`sec-reviewer` 在可审计证据中无任何输入/发现/审批/sign-off。
- **P1 验证恢复不可审计**：task context 全为 `iteration:1`，无失败/重试/override 痕迹。
- **P1 评估未闭合**：`WORKFLOW_EVALUATION.md` 五大反馈段全为占位符。
- **P1 统计证据弱**：`test_count_actual: N/A (collection failed)` 下仍出具"0 failed"。
- **P2 critical_flows 缺 IDOR**：IDOR 仅在 `forbidden_flows`，未提升为顶层关键流。
- **P2 projects_api 授权语义歧义**：plan 描述"POST/PUT/DELETE 仅 admin"与"member 不可删他人 project"自相矛盾。

## 系统改进建议（转化为可登记项）

1. **UX-18b（P1）**：`_check_workflow_evaluation` 应检测占位符内容（如"待补充/TODO/(待 foreman"），章节存在但实质为空时判 FAIL，堵住 header-only 骨架绕过。
2. **FL-48（P1）**：验证恢复闭环需留痕。`coverage_gate` 类首次预期失败的任务，应在 task context 写入 `iteration>1 / last_error / override 决策`，否则 retry/override 无法审计。
3. **FL-49（P1）**：reviewer/auditor 角色需"有效参与"证据。foreman 创建非执行者角色后，应要求其产出可审计的 review sign-off（FL-45 已解决"是否创建"，未解决"是否参与"）。
4. **RV-22（P2）**：validate/verification 应对 critical_flows 中的写端点做"授权覆盖"形式检查 —— 若某写端点在 acceptance/测试矩阵中缺角色用例，给出 warning（针对 `POST /projects` 这类授权口径例外）。
5. **FL-50（P2）**：verification 测试应至少跑一次"打乱顺序/随机种子"或独立进程隔离，以暴露 `test_config` reload 这类顺序依赖（默认顺序全绿掩盖真实缺陷）。
6. **UX-19（P2）**：评估摘要在 `test_count_actual: N/A (collection failed)` 时不得出具"0 failed"绝对结论，应降级为"未采集/不可信"。
