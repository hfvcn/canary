## 关键问题与改进建议

### 高优先级

1. **SSRF 防护未接入业务路由** — `validate_callback_url()` 作为独立函数存在但未被任何 API endpoint 调用。需要将其集成到 ShareLinkCreate 的验证流程中。同时需处理 IP 编码变体（十六进制、八进制）。
   - **系统改进**：plan.yaml 的 verification.checks 应包含端到端 SSRF 测试（从 API 层发请求），而非只检查函数是否可导入

2. **FTS5 中文搜索名不副实** — `unicode61` 是字符级 tokenizer，不支持中文分词。真正的中文搜索需要 jieba 或 ICU tokenizer。
   - **系统改进**：Aegis 规则应对 FTS5+中文场景强制要求分词验证用例（子串匹配而非整串匹配）

3. **所有任务 verification_force_passed** — 说明 workflow 验证闭环不完整。正常流程应有 verification_passed 信号。
   - **系统改进**：调查 force_passed 的根因 —— 是 verification 命令设计问题还是 workflow engine 问题

### 中优先级

4. **Worker-1 未真正启动** — desired_state=running 但 runtime_state=stopped。Foreman 自执行全部任务，未测试到多 actor 并行场景
5. **verification 命令过浅** — 大多只检查 import 和路由数量，不验证业务行为
6. **coverage-gate 与 integration-tests 重复** — 可删除或合并

### 低优先级

7. **search.py 静默降级** — 捕获 OperationalError 返回空列表
8. **测试间重复** — tag autocomplete 和 SSRF 在多个测试文件中重复
9. **batch_e2e_command 截断** — `| tail -30` 可能丢失关键错误上下文
