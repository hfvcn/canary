## 新发现

### FL-17b solve flow state.json 清除仍未生效（P2 — 复现）

> **来源**：2026-05-17 E2E v39 启动阶段
- **严重度**：P2 — 阻塞新 flow 启动
- **现象**：上一次 solve flow 完成后 `.ralph-flow/state.json` 残留。运行 `ralph flow start e2e` 创建了新 state，但 `ralph flow next` 报 "Flow solve completed" 读取了旧状态
- **根因**：FL-17 代码修复可能未覆盖"从另一个工作目录启动 flow"的场景，或 state.json 写入路径与读取路径不一致
- **验收标准**：solve flow 完成后 `.ralph-flow/state.json` 不存在

### UX-13 Foreman 未在 workflow.completed 后自动生成 WORKFLOW_EVALUATION.md（P3）

> **来源**：2026-05-17 E2E v39 step 4
- **严重度**：P3 — 体验改进
- **现象**：workflow.completed 事件发出后，foreman 未主动生成 WORKFLOW_EVALUATION.md。需要 observer 显式发消息要求
- **改进方案**：foreman system prompt 或 workflow completion handler 中加入自动生成 evaluation 的指令

### UX-14 T1 冷启动 stall 需更好处理（P3）

> **来源**：2026-05-17 E2E v39 T1 执行
- **严重度**：P3 — 不影响结果但影响体验
- **现象**：Worker-1 首个任务 T1 在 300s 时触发 stall warning（308s/340s/370s），实际在 370s 后完成
- **改进方案**：首个任务的 stall 阈值可适当放宽（如 600s），或 foreman 在分配首个任务时预告 "cold start may take longer"
