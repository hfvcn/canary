## 七、后续改进及对应实例

### [RO-60] verification 命令 shell 语义

**优先级**：P0
**影响维度**：过程 + 体验
**预期分数变化**：过程 3→4, 体验 3.5→4

**触发实例**：
> v23 T1 verification check command `PYTHONPATH=backend python -c '...'` 被 subprocess 解释为查找名为 `PYTHONPATH=backend` 的可执行文件，报 `[Errno 2] No such file or directory`。代码完全正确但验证失败。

**根因**：`ralph_service.py` 的 verification runner 对不含 shell 操作符（`&&`, `||`, `|`, `;`）的命令使用 `subprocess.run(shlex.split(cmd))`，不经过 shell。`VAR=val cmd` 是 shell 语法，不是 exec 语法。

**改进方案**：(A) 扩展 shell 操作符检测，增加 `VAR=` 模式检测；或 (B) Ralph validate 对 verification command 中包含 `VAR=val` 模式发出 warning。

**验收标准**：`PYTHONPATH=backend python -c '...'` 格式的命令能正确执行。

---

### [RO-61] plan_digest_divergence 分级

**优先级**：P0
**影响维度**：过程 + 体验
**预期分数变化**：过程 3→4, 体验 3.5→4.5

**触发实例**：
> v23 Foreman 修改 plan.yaml 的 verification command（从 `PYTHONPATH=...` 改为 `sh -c '...'`），导致 20 次 `plan_digest_divergence`，4 个任务全部需 `--force` 完成。

**根因**：digest guard 对 plan.yaml 做全文 hash，不区分核心字段（task ID / depends_on / claimed_paths）和运维字段（verification.checks.command）。

**改进方案**：将 digest 分为 structural digest（核心字段）和 operational digest（运维字段）。structural 变更严格 guard，operational 变更只发 advisory warning。

**验收标准**：修改 verification command 后 task complete 不被 digest guard 阻塞。
