## 交叉验证

### Results Review (Codex, verdict=revise, confidence=4/5, score=84/100)

1. **🔴高危：JWT sub 类型注入 → 500** — `app/auth.py:47` 只检查 `sub` 存在性，`app/auth.py:54` 直接 `int(user_id)`，合法签名但 `sub="abc"` 的 token 触发 500 而非 401。测试未覆盖此分支。
2. **🟡中危：JWT 默认密钥** — `app/config.py:5` SECRET_KEY 默认 `"dev-secret-key-change-in-production"`。部署漏配则攻击者可自签 token。（RO-113 历史问题复现）
3. **🟡中危：任务领取非原子操作** — `app/routers/tasks.py:99-117` 先读 pending 再写回，无条件更新/锁，并发 worker 可能双领取。
4. **🔵低危：RBAC 测试残留代码** — `tests/test_rbac.py:15-29` 有未使用变量和 pass。
5. **✅角色注入防护通过** — `app/schemas.py:9` 使用 `extra="forbid"`，测试验证了 role/is_admin/is_superuser/permissions/scope 被拒绝。权限来自数据库 membership 而非 JWT claims。

## v57 新发现

### FL-67（P2：plan.yaml state 段不记录 override 完成的任务）

plan.yaml state 段只登记了 8 个正常完成的任务，遗漏了通过 foreman_override 完成的 T3 和 T4。
这导致 plan.yaml 作为执行记录不完整——台账显示 10/10 完成但 plan.yaml 只记录 8/10。

### FL-68（P2：security-reviewer 创建但未实际分配安全审查任务）

foreman 创建了 security-reviewer actor 满足"非执行者角色"要求，但 T10-security-review 实际被派给了 worker-a 而非 security-reviewer。安全审查的独立性要求只在形式上满足。

### FL-69（P2：claimed_paths 不精确导致大量越界告警）

T8 需要修改三个 router 但只 claim 了 audit.py/test_audit.py。T5/T6 需要挂载 main.py 但未申领。
validate 时已产生 W_WORKER_EXCEEDED_SCOPE 越界告警，但不阻塞执行。

### FL-70（P3：WORKFLOW_EVALUATION 过程摩擦记录不完整）

WORKFLOW_EVALUATION.md 未记录：T3 task_failed/task_deferred 事件、多次 W_WORKER_EXCEEDED_SCOPE 告警、T9 快速 compile-check。评估文档对验证覆盖和流程摩擦的表述过度乐观。

### RV-53（P2：auth.py sub 类型注入 → 500 而非 401）

应用级安全缺陷：JWT sub 字段为非整数字符串时，auth.py 的 `int(user_id)` 抛出 ValueError → 500。
validate 和 verification 均未检测此类"认证边界畸形输入"场景。

### RV-54（P3：task claim 非原子操作，并发竞争窗口）

tasks.py claim_task 先读 pending 再写回无锁，并发 worker 可能双领取。
validate 不检测此类"状态机并发安全"问题。

## 改进建议

1. **WORKFLOW_EVALUATION 定性章节强制非空闸门**（UX-23 持续复现）：step-3 或 verification 应检查定性章节至少有实质内容（>100 字），不能只检查章节标题存在。
2. **plan.yaml state 段记录 override 完成**（FL-67）：foreman_override 事件应同步更新 plan.yaml state。
3. **security-reviewer 分配验证**（FL-68）：validate 应检查安全审查任务是否分配给了声明的 security-reviewer 角色。
4. **claimed_paths 越界告警升级**（FL-69）：W_WORKER_EXCEEDED_SCOPE 应在 verification 阶段计入评分，连续越界应触发 review_required。
5. **auth 畸形输入检测规则**（RV-53）：validate 应检查认证依赖是否对 JWT claims 做了类型安全转换。
