### 新发现

#### RO-34 Actor restart 后 inbox 消息不重投递
- **严重度**：Medium — Foreman 重启后沉默直到有新消息触发投递
- **现象**：消息在 17:49:50 通过 pty 投递给 runtime_state=stopped 的旧进程；17:50:49 restart 后新进程不重投递，Foreman idle 8 分钟
- **根因**：daemon delivery 层把 pty_submit_text 成功视为"已投递"，不跟踪消费确认
- **改进方案**：restart 后检查 inbox pending 消息，对未确认消费的消息重新投递
- **触发实例**：v15 首轮环境中 Foreman restart 后 idle 8 分钟，需要手动发送提醒消息才恢复

#### RO-35 Gemini CLI trust directory 导致 Ralph Agent 失败
- **严重度**：Medium — 已修复
- **现象**：`ralph validate` 在非信任目录（如 /tmp/）运行时 Gemini CLI 返回 exit code 55
- **根因**：Gemini CLI v0.40+ 要求运行目录被显式信任；Ralph Agent subprocess 调用不带 `--skip-trust`
- **修复**：在 `_gemini_command()` 中加 `--skip-trust`
- **状态**：已修复，v15 第二轮验证通过

#### 批次自动推进（Foreman 建议）
- Foreman 建议引擎在 tasks_ready 时自动提交下一批，无需手工 submit
- 这是 v15 体验的主要摩擦来源
- 可考虑作为 FIX-11 在下一轮实现
